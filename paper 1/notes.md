# Phase 1 — Notes

## 1. Training, Test and Validation Data

All data is synthetically generated by `src/generate_data.py`. No real-world capture was used.

| Split | File | Size |
|---|---|---|
| Train | `data/train.csv` | 8,000 samples (80%) |
| Validation | `data/validation.csv` | 1,000 samples (10%) |
| Test | `data/test.csv` | 1,000 samples (10%) |
| Held-out | `data/held_out.csv` | 4,000 samples (separate generation) |

**Schema:** each row has a `text` column (a shell command string) and a `label` column (integer).

**Classes (binary):**
- `0` — Benign
- `1` — T1003.002 (OS Credential Dumping: SAM registry hive exfiltration)

**Malicious samples** are variations of `reg save`/`reg export` targeting sensitive hives:
- Hives: `HKLM\SAM`, `HKLM\SYSTEM`, `HKLM\SECURITY` (and their full `HKEY_LOCAL_MACHINE\...` forms)
- Output paths: `C:\Windows\Temp\`, `C:\Temp\`, `%TEMP%\`, UNC paths (`\\localhost\c$\`)
- Wrappers: bare command, `cmd.exe /c`, `powershell -command`, `CMD /C powershell -c "..."`, `Pwsh -noprofile -c`, `powershell -exec bypass -w hidden -c`, etc.
- Obfuscation: random mixed-case (`normalize_case`), variable whitespace (1–3 spaces)

**Benign samples** cover legitimate registry operations:
- Actions: `query`, `add`, `delete`, `copy`, `compare`, `restore`, `unload`, `save`
- Hives: `HKCU`, `HKU`, and safe `HKLM` sub-keys (Software\Policies, Wow6432Node, etc.)
- Benign `HKLM save` commands are forced 60% of the time when the action is `save`, to teach the model that saving non-sensitive HKLM keys is not malicious.
- Hard-coded critical negative samples (e.g., bare `reg.exe`, `reg save`, `wmic.exe`, `powershell.exe`) ensure the model does not fire on partial/ambiguous inputs.
- Persistent false-positive fixtures (e.g., `reg save HKEY_LOCAL_MACHINE\SOFTWARE ...`) are injected into every split to suppress known FP patterns.

## 2. Test Methodology

Script: `src/evaluate_model.py`  
Dataset: `data/test.csv` (1,000 held-in samples from the same generation run as train/val)

**Steps:**
1. Loads tokenizer from the merged model dir (`models/merged_roberta_bitfit_model`) with a fallback to the adapter path or the base model hub ID.
2. Filters the dataset to label ∈ {0, 1}.
3. Tokenises with `max_length=128`, `padding="max_length"`, `truncation=True`.
4. Loads the model — tries PEFT adapter + `merge_and_unload()` first; falls back to loading the full merged model directly.
5. Runs the HuggingFace `Trainer.evaluate()` in bf16 (if CUDA available) with `per_device_eval_batch_size=64`.
6. Computes: accuracy, precision, recall, F1 (binary average), MCC, and prints the confusion matrix.
7. Saves results to `results/final_test_results/final_evaluation_metrics.json`.

## 3. Stress Test Methodology

### 3a. Held-out benchmark — `src/benchmark.py`
Dataset: `data/held_out.csv` (4,000 samples generated independently from the train/val/test run)

**Steps:**
1. Loads the base `roberta-base` model and attaches the BitFit adapter from `models/final_roberta_bitfit_model`.
2. Runs batched inference (batch size 64) over all 4,000 commands.
3. Converts numeric predictions back to label names.
4. Reports: overall accuracy, confusion matrix (as a markdown table), and a full per-class `classification_report` (precision, recall, F1 at 4 decimal places).

## 4. Training Methodology

Script: `src/trainer.py`

1. **Seed**: `set_seed(42)` for full reproducibility.
2. **Base model**: `roberta-base` loaded from HuggingFace Hub as a sequence-classification head with 2 output labels.
3. **PEFT / BitFit**: `BitFitConfig(bias="all", task_type="SEQ_CLS")` — only bias terms are trainable. LoRA (`r=8`, `lora_alpha=32`) is used as a fallback if the installed PEFT version does not expose `BitFitConfig`.
4. **Gradient checkpointing** + `enable_input_require_grads()` are enabled to reduce VRAM.
5. **Dtype**: `torch.bfloat16` on GPU.
6. **Tokenisation**: `max_length=128`, `padding="max_length"`, `truncation=True`; `labels` column passed through directly.
7. **Dataset filtering**: only rows with `label ∈ {0, 1}` are kept.
8. **Evaluation metrics** (computed every 50 steps on the validation set): accuracy, precision, recall, F1 — all using `binary` averaging.
9. **Best-model selection**: `load_best_model_at_end=True`, tracked by F1.
10. **Early stopping**: patience = 6 evaluation checkpoints, threshold = 0.005 improvement.
11. **Saved to**: `models/final_roberta_bitfit_model/`; merged (adapter weights baked in) to `models/merged_roberta_bitfit_model/` via `src/merge_adapter.py`.

## 6. How the App Works (Step-by-Step)

The inference API is a Flask application in `app.py`.

### Startup
1. Scans `models/` for any directory whose name starts with `"merged"` (picks the first match). Falls back to `models/merged_deberta_model` if nothing is found.
2. Loads `AutoModelForSequenceClassification` from that directory using `torch.bfloat16` on CUDA or `float32` on CPU, then moves the model to the detected device.
3. Loads the matching `AutoTokenizer` from the same directory.
4. Reads `model.config.id2label` to get the label map at runtime (no hard-coded labels in `app.py`).
5. Flask starts listening on `0.0.0.0:8000`.

### Inference request — `POST /predict`
1. **Input extraction** (tried in order):
   - JSON body: `{"text": "<command>"}` (requires `Content-Type: application/json`)
   - Form data: `text=<command>`
   - Raw body fallback: entire body treated as the command string; if the body looks like a JSON object but failed to parse, a lenient string-extraction heuristic pulls out the `"text"` value.
2. Returns `400` with `{"error": "Missing 'text' field ..."}` if no text could be extracted.
3. **Tokenisation**: `tokenizer(text, return_tensors="pt", max_length=128, padding="max_length", truncation=True)` — mirrors the training preprocessing exactly.
4. All tensors are moved to the model's device.
5. **Forward pass** under `torch.no_grad()` → raw logits tensor of shape `[1, num_labels]`.
6. `torch.argmax(logits, dim=1)` gives the predicted class index.
7. `torch.nn.functional.softmax(logits, dim=1)` gives per-class probabilities; the probability of the predicted class is returned as `confidence_score`.
8. **Response** (JSON):
   ```json
   {
     "input_text": "<original command>",
     "predicted_label": "Benign" | "T1003.002",
     "confidence_score": 0.9998
   }
   ```

### Other endpoints
- `GET /` — returns a simple HTML page describing the API.
